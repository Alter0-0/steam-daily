# Steam 今日情报：新手操作说明

云端自动采集版本已准备，部署说明见项目根目录的 `CLOUD-SETUP.md`。只有完成 GitHub 部署后，才能在电脑关机或休眠时继续采集。本说明下面的操作均为本机版。

这个工具会从 Steam 公开商店读取当天的新游戏和 Demo，然后在本机网页中显示日报。

“本机运行”指的是：程序运行在你自己的电脑上，其他人无法通过互联网访问。网页地址中的 `127.0.0.1` 也是本机地址。

## 一、先确认项目文件夹

本项目文件夹是：

```text
C:\Users\xbjy2\Documents\Codex\2026-09-30\steam-demo-demo-steam-chatgpt-work
```

打开文件资源管理器，把上面的路径复制到顶部的地址栏，然后按回车。你应该能看到这些文件：

- `start-server.cmd`：启动日报网页
- `run-collector.cmd`：手动采集 Steam 数据
- `install-schedule.ps1`：设置每天自动采集
- `outputs` 文件夹：网页文件所在位置
- `data` 文件夹：日报数据和运行状态

请不要直接双击 `outputs` 文件夹里的 `steam-daily.html`。直接双击会打开演示数据页面，不会读取实时日报。

## 二、第一次设置（只需要做一次）

### 1. 打开 PowerShell

点击 Windows 开始菜单，搜索 **PowerShell**，打开“Windows PowerShell”。会出现一个蓝色或黑色窗口，这个窗口是用来输入命令的。

### 2. 进入项目文件夹

把下面这一整行复制到 PowerShell，然后按回车：

```powershell
cd "C:\Users\xbjy2\Documents\Codex\2026-09-30\steam-demo-demo-steam-chatgpt-work"
```

### 3. 第一次采集数据

在同一个 PowerShell 窗口中输入：

```powershell
node collector.mjs
```

按回车后请等待一两分钟。程序会读取 Steam 数据，第一次运行会建立“商品页基线”。这意味着第一次运行只记录当前已知页面，之后新出现的页面才会被标记为“新发现商品页”。

如果最后看到类似下面的文字，说明采集完成：

```text
Collected 80 games; report 2026-09-30
```

如果看到 `fetch failed`，通常是网络暂时无法访问 Steam。可以稍后重试；现在成功项目会保存并显示“部分完成”，失败项目留到下次续采。

### 4. 设置每天自动采集

仍然在项目文件夹对应的 PowerShell 窗口中输入：

```powershell
powershell -ExecutionPolicy Bypass -File .\install-schedule.ps1
```

看到下面两行就表示设置成功：

```text
SteamDailyCollector installed; it runs daily at 04:00 and retries failed runs every 30 minutes.
SteamDailyServer added to the current user Startup folder.
```

之后 Windows 会每天中国大陆时间 04:00 自动采集。如果采集失败，任务会每隔 30 分钟自动重试，最多重试 8 次；任务允许在电池供电时运行，也会在错过计划时间后尽快补运行。

### 5. 启动网页

回到项目文件夹，双击 `start-server.cmd`。如果服务还没有运行，会出现一个命令窗口，请保持这个窗口打开；可以把它最小化，但不要关闭。如果服务已经在运行，脚本会提示“already running”，这时直接使用浏览器即可。网页服务意外退出时，后台守护脚本会自动尝试重新启动。

然后在浏览器地址栏打开：

http://127.0.0.1:4173/steam-daily.html

看到页面顶部写着“实时数据 · 本地采集器”，说明网页正在读取真实日报。

## 三、以后每天怎么使用

完成第一次设置后，每天只需要：

1. 确认 `start-server.cmd` 已经运行。通常登录 Windows 后它会自动启动；如果没有，回到项目文件夹双击它。
2. 在浏览器打开 <http://127.0.0.1:4173/steam-daily.html>。
3. 使用日期按钮和日期下拉框查看近期日报；点击“查看全部历史”选择更早日期。日报长期保存，全局搜索也包含旧存档。

不需要每天重新运行 `install-schedule.ps1`。也不需要每天双击 `steam-daily.html`。

日报在每天 04:00 生成前一天的数据。例如 10 月 1 日凌晨生成的是 9 月 30 日日报。

## 四、想立即更新时怎么做

如果不想等到第二天 04:00，可以在项目文件夹中双击 `run-collector.cmd`，等待窗口中的采集完成文字出现，然后在浏览器按 `Ctrl + R` 刷新网页。

也可以在 PowerShell 中运行：

```powershell
cd "C:\Users\xbjy2\Documents\Codex\2026-09-30\steam-demo-demo-steam-chatgpt-work"
node collector.mjs
```

采集过程可能需要几分钟，因为每款游戏都要读取详情和测评。采集完成前不要关闭窗口。

## 五、页面显示“演示数据”怎么办

最常见的原因是打开了错误的地址。请看浏览器地址栏：

- 正确：`http://127.0.0.1:4173/steam-daily.html`
- 错误：`file:///C:/Users/.../outputs/steam-daily.html`

如果地址以 `file:///` 开头，请把地址替换为正确的 `http://127.0.0.1:4173/steam-daily.html`。

如果正确地址仍然打不开：

1. 回到项目文件夹。
2. 双击 `start-server.cmd`。
3. 保持弹出的窗口打开。
4. 回到浏览器，重新打开正确地址。

## 六、查看采集是否成功

在项目文件夹中打开 `data` 文件夹，找到 `status.json`。用记事本打开它：

- `"state": "success"`：最近一次采集成功。
- `"state": "error"`：最近一次采集失败或仍有日期缺漏，页面保留已保存的结果。
- `"state": "partial"`：新日报部分完成，成功项目已保存，其余会继续重试。
- `"message": "fetch failed"`：通常是 Steam 或网络暂时不可访问。

`data\state.json` 是实际日报数据文件，请不要手动编辑或删除。删除它会丢失商品页首次发现记录，下一次运行会重新建立基线。

## 七、常见问题

### 黑色窗口可以关闭吗？

如果窗口显示正在启动服务，不能关闭它；关闭它会停止网页服务，浏览器就无法读取实时数据，可以点击最小化按钮把它放到后台。如果窗口提示服务已经在运行，可以关闭这个提示窗口，因为原来的服务仍在运行。

### 电脑关机时会采集吗？

关机时无法联网采集。任务已设置为错过计划时间后，在电脑下次可用时尽快运行，但电脑需要重新开机并登录。

### 为什么日报日期是昨天？

日报在每天 04:00 生成前一天的完整数据，这是设计行为，不是日期错误。

### 为什么有些游戏没有好评率？

新页面可能还没有测评，或测评请求失败。页面会显示“暂无”；完整日报保留生成时的快照，不会每天重新刷新历史好评率。

## 当前功能

### 某天的日期缺失怎么办？

采集器现在会自动检查最近 30 天中缺失的日期，并在网络恢复后的采集任务中补查，无需每天手动操作。日历出现“待补采”表示当天没有成功保存数据，不能理解为当天没有新游戏。

补采只能恢复 Steam 当前能够核实的游戏及 Demo 发售信息。价格和测评会标明为补采时数据；当天首次出现的商品页、给旧游戏新增的 Demo 按钮，以及当时的价格和测评历史无法准确恢复。搜索覆盖不完整时会继续保留“待补采”状态并重试。

自动任务以隐藏窗口运行，结果会写入 `data\collector.log`。网页服务窗口和采集任务是不同进程，关闭网页服务不会停止隐藏的采集任务。

- 首页近30天日报、日期阶梯，以及长期历史存档
- 当天发售、新发现商品页、新出现 Demo
- 封面、价格、免费状态、标签、发售日期、开发商、发行商、Steam 链接
- 总体好评率和测评数量
- 按好评率、发售时间、价格排序
- 按标签筛选、搜索游戏名称、只看 Demo
- 自动排除 DLC、原声带和支持者包

Steam 不提供商品页创建历史，因此“新发现商品页”表示采集器第一次看到该 App 的日期。Steam 只有日期、没有具体时间时，页面会保留 Steam 返回的日期文本。
