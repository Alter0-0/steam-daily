# Steam 日报

每天北京时间 04:00 开始整理前一天的游戏发售、近期首次发现的商品页和 Demo。云端按小时触发续采；最近 7 天会持续复查搜索结果（最多每 6 小时重新扫描一次），每 7 天回查最近 30 天，首次升级立即启动 30 天回查。使用 GitHub Actions 和 GitHub Pages，采集不依赖个人电脑开机。

日期优先使用商店页面可核实的上线时间戳并换算北京时间；商店原始日期会保留。抢先体验旧时间戳不会冒充正式版时间；使用正式版公告时明确标为公告时间。没有可靠时刻时保留 Steam 日期并注明未核实，不统一加一天。

搜索发现的 AppID 先持久保存，再请求详情、测评和时间依据。详情失败时网页仍展示带有待核实标记的条目；后续补齐信息。历史日报采用追加与日期校正，保留已知价格、测评及其原始快照时间，新增历史记录标明补录时间。复查通过表示该搜索窗口运行通过，不代表 Steam 全量覆盖。

日报长期保存，不因超过30天删除。首页默认浏览近30天，点击“查看全部历史”选择更早日期；旧日报按月加载。全局搜索覆盖全部存档，首次打开时读取历史名称目录，点击结果再加载对应月份。支持按好评率或评论量排序、标签筛选、名称搜索和只看 Demo。评论量排序将各分类中评论最多的游戏放在前面，数量相同时优先显示好评率较高的游戏；数量以日报采集时的测评数据为准。

搜索有两个独立入口：“搜索当前日报”配合当日标签和 Demo 筛选使用；页面上方“搜索全部日报”查询本站目前保留的所有日报，支持中文名、英文名、部分名称和 AppID，不受当日筛选影响。同一游戏合并展示，并列出各日期和栏目；点击日期后跳转并突出对应游戏，同时清除当日搜索、标签和 Demo 筛选。仅打开或关闭全局搜索不会改动当日筛选。结果可继续加载，没有仅显示前30款的总量限制。尚未采集的游戏、尚未补齐的中文名无法凭空检索。

部署步骤见 [CLOUD-SETUP.md](CLOUD-SETUP.md)，本机操作见 [outputs/README.md](outputs/README.md)。

```sh
node --test work/history.test.mjs work/cloud.test.mjs work/phase1.test.mjs work/search.test.mjs
node cloud/build.mjs
```

Steam 限流、第三方服务故障或 GitHub 调度延迟时，日报可能部分完成。程序保留成功结果、标明缺漏并重试，不承诺全量搜索覆盖或绝对可用性。Steam 没有公开的完整商品页创建时间历史；新发现不等于当天新建。

云端入口是 `node cloud/run.mjs`，也可在独立的测试副本执行 `node phase1-collector.mjs --review-30` 强制进行 30 天回查。每轮运行最多采集约 30 分钟，搜索游标、发现记录和详情待办保存在 `daily-data` 分支，下一轮继续；不会因一个长期失败的项目阻塞整队。

长期保存、近期浏览和自动复查是三个独立范围。已完成资料的30天前游戏停止例行刷新；历史未补齐条目继续轮流补录，明确指定的旧游戏也可优先核验。历史价格和测评仍为原快照，不把今天查询的数值冒充旧数据。2026-10-23从数据分支历史版本找回9月19日至22日4期日报，恢复时保留来源版本、不覆盖已有日期。详见 [长期存档说明](ARCHIVE.md)。
